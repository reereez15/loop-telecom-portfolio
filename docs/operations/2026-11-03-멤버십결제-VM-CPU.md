# 2026-11-03 멤버십 카카오페이·VM CPU 배포 안내

## 적용 범위
- Plus 14,900원, VIP 29,900원. 서버에서 금액을 결정한다.
- 기존 membership_accounts에는 만료일이 없어 요청에 따라 1회 구매 후 영구 유지한다. 자동 갱신 없음.
- Plus → VIP는 29,900원 전액 결제. 차액 정산 없음.
- 무료 가입 후 현재 등급보다 높은 등급만 구매 가능. ADMIN 역할이나 포인트에는 영향을 주지 않는다.
- 새로운 DB 테이블·컬럼·ORM 모델·마이그레이션 없음. 이 작업 때문에 db upgrade/create_all을 실행하지 않는다.
- 기존 security_audit_logs에 action=membership.purchase 및 membership.redirect로 구매·결제창 정보를 기록한다. 통신요금 invoices/payments와 혼합하지 않는다.

## 결제 배포
백엔드와 프런트엔드를 함께 빌드·배포한다. 백엔드만 기존 버전이면 새 구매 API가 404가 된다.
기존 배포 환경에 KAKAOPAY_SECRET_KEY, KAKAOPAY_CID 및 PUBLIC_BASE_URL 설정이 필요하다.
실제 공개 주소가 HTTPS이면 PUBLIC_BASE_URL=https://192.168.3.30 으로 설정한다.
카카오페이 측 가맹점 설정에서 해당 복귀 URL을 허용해야 하며, 실제 발급된 Secret Key와 CID를 사용한다.
TC0ONETIME은 테스트 가맹점이다. 실제 유료 판매를 하려면 운영 가맹점 계약·키가 필요하다.
키는 프런트엔드·Git·채팅에 넣지 않는다.

복귀 경로: /membership/kakaopay/approve, /cancel, /fail.
승인 전에는 등급을 변경하지 않는다. 승인 금액·tid·주문 ID·사용자 ID를 모두 검증한다.
구매 ID는 membership-<audit row ID> 형식으로 통신요금 결제 ID와 구분한다.
CSRF·로그인·고객 역할·소유권 검사 및 멱등 키·계정 행 잠금을 사용한다.

### 운영 확인
- security_audit_logs의 membership.purchase / membership.redirect 행은 결제 업무 기록이므로 정리 작업에서 삭제하면 안 된다.
- PREPARING/APPROVING: 프로세스 종료 등으로 중간에 멈췄을 수 있다. 카카오페이 거래 내역과 대조한다.
- REVIEW: 준비/승인 응답을 확인할 수 없거나 결제 후 등급 반영에 실패한 상태. 재결제를 막는다.
- REFUND_REQUIRED: 승인 정보가 일치하지 않고 전체 취소도 확인되지 않은 상태. 운영자가 PG와 대조·환불해야 한다.
- 위 상태는 브라우저의 취소 버튼으로 해제하지 않는다. 거래 확인 없이 상태를 수동으로 바꾸지 않는다.
- 기존 통신요금 관리자 환불 API는 이 구매를 처리하지 않는다. 멤버십 환불·등급 조정은 PG 확인 후 운영자 처리 대상이다.
- 결제 모듈은 모의 PG 응답으로 검증했다. 실제 PG 승인·실결제는 실행하지 않았다.

## VM CPU 표시
새 API는 vm_cpu 배열에 PC1 VM / PC2 VM CPU와 최근 1시간 추이를 제공한다.
기존 Windows CPU·RAM·C드라이브, VM ON/OFF, 서비스 감시는 유지한다.

기본 Zabbix 기술 호스트명:
- pc1-k3s: 192.168.7.185
- pc2-k3s: 192.168.7.100

호스트명이 다르면 API 서버 환경변수 ZABBIX_PC1_VM_HOST / ZABBIX_PC2_VM_HOST로 지정한다.
VM 주소 변경 시 기존 ZABBIX_PC1_IP / ZABBIX_PC2_IP도 맞춘다.
VM 이름의 대소문자는 실제 Zabbix 기술 호스트명과 일치해야 한다.

2026-11-03 조회 시 현재 Zabbix에는 telecom-services, PC1-Windows, PC2-Windows, Zabbix server만 등록되어 있었다.
VM의 CPU는 Ping/TCP 응답만으로 측정할 수 없다. VM마다 Zabbix Agent/Agent2 설치 후 Linux 템플릿으로 수집해야 한다.
Zabbix 웹의 Data collection → Hosts → Create host에서 위 기술 호스트명으로 등록하고,
Linux by Zabbix agent active 템플릿과 읽기 토큰이 접근 가능한 호스트 그룹을 연결한다.
VM 에이전트의 Hostname은 위 기술 호스트명과 같아야 하고, ServerActive는 에이전트에서 도달 가능한 Zabbix 서버 주소:10051이어야 한다.
현재 Windows 에이전트가 사용하는 서버는 PC2 Windows 192.168.3.19:10051이다. VM에서 이 주소로 라우팅/방화벽 통신이 가능한지 먼저 확인한다.
Linux VM의 에이전트 설정·서비스 설치와 Zabbix 호스트 생성은 이번 로컬 소스 수정에서 실행하지 않았다.

수집 지원 항목:
- system.cpu.util / CPU utilization (전체 CPU 사용률)
- 또는 system.cpu.util[,idle] (100 - idle로 계산)
180초 초과·미수집·오류·범위 밖 수치는 수집 대기로 표시한다. Windows 값을 VM 값으로 대체하지 않는다.
