# 04 · 개선점과 느낀 점

## 1. 문제 → 원인 → 해결 → 결과

### ① 공개 저장소에 Discord 웹훅과 API 토큰이 남아 있었다
- **문제**: 개인 저장소로 옮기려고 점검하니 n8n 워크플로 JSON 5개에 Discord 웹훅 1개, 커밋 기록에 자동화 API 토큰 3개가 있었다.
- **원인**: n8n에서 내보낸 워크플로에 HTTP 헤더 값(`X-API-Key`)과 웹훅 주소가 그대로 들어간다. 커밋 전 점검 단계가 없었다.
- **해결**: `scripts/sanitize_repo.py` — 기록 전체에서 값을 찾아 `git filter-repo`로 치환. 워크플로는 `{{ $env.AUTOMATION_API_TOKEN }}`처럼 환경변수를 읽도록 바꿈(`localize_monitoring.py`). 제출 전 `check_secrets.py --history`.
- **결과**: 커밋 246개 재작성, 값 4개 제거, 재검사 0건. 팀에 웹훅 재발급·토큰 교체 요청.

### ② 계정 브루트포스 탐지 규칙이 실제 앱 로그와 맞지 않았다
- **문제**: Graylog `ED-08 동일 계정 브루트포스`는 `rule:login-bruteforce AND username:*`을 찾는다. 내가 만든 API는 `event_type:auth.login.failed`와 `account_hash`로 남기고 `username`은 남기지 않는다. 그래서 이 규칙은 모의 로그로만 검증됐다.
- **원인**: 시험용 모의 로그 형식(D)과 앱 표준 이벤트 형식(A)을 서로 확인하지 않았다. 이메일을 로그에 남기지 않기로 한 내 설계가 규칙 쪽에 전달되지 않았다.
- **해결**: Graylog 규칙을 `event_type:auth.login.failed`, `account_hash`별 count ≥ 5, 15분 창으로 새로 만들고 알림을 n8n `login-bruteforce`로 연결. n8n 잠금 노드는 이미 `account_hash`를 받으므로 수정 불필요.
- **결과**: 앱 내부 재현 8/8 통과(999~1,142 ms). Graylog 경유 실측은 로컬 설치 후 기입 → ⬜

### ③ 멤버십 등급 구매 기능이 팀원 작업과 겹쳐 되돌렸다 (11-02 ~ 11-03)
- **문제**: 등급 직접 구매(카카오페이·모의 카드)를 붙였는데(`250b42c`), 같은 날 `main`에 문경구 님의 멤버십 결제 작업(`725990c`)이 들어와 충돌.
- **원인**: 같은 기능을 두 브랜치에서 동시에 만들었다. 역할표상 웹은 A였지만 기능 단위 담당을 정하지 않았다.
- **해결**: 결제 테이블 없이 `tid` 쿠키로 처리하도록 줄인 뒤(`74372f8`) 최종적으로 내 구현을 되돌리고(`5d62b7b`) `main`의 구현을 살렸다.
- **결과**: 발표 전 충돌 없이 병합(PR #62). 이후 기능 시작 전에 이슈로 담당자를 먼저 적기로 함.

### ④ 자동 로그아웃 시간을 하루에 두 번 바꿨다
- **문제**: 1시간으로 늘렸다가(`602812c`) 같은 날 30분으로 줄임(`2132bde`).
- **원인**: 시연 편의와 보안 기준 사이에서 근거 없이 정했다.
- **해결**: 유휴 30분·최대 8시간을 `config.py` 상수로 두고 화면에 남은 시간을 표시. 테스트로 고정.
- **결과**: 값 하나만 바꾸면 되고 테스트가 확인한다.

### ⑤ 새 PC에서 혼자 설치할 수 없었다
- **문제**: Graylog·n8n·Wazuh 실행 정의가 저장소에 없음, `.env.example`에 앱이 읽는 값 8개 누락, 로컬 실행에서 관리자 화면 접근 불가, 시드 실행 불가.
- **원인**: 각자 PC에서 설정하고 결과만 공유했다.
- **해결**: `monitoring.compose.yaml`, `compose.portfolio.yaml`(관리자 입구 8444, 시드 연결), `.env.example` 보완, 설치 가이드.
- **결과**: 단계별 확인 명령 정리. 본인 PC 실측 ⬜

## 3. 시간이 더 있다면

- n8n 워크플로 `신규 API - 계정 잠금 해제(관리자)`가 `/api/admin/customers/1/unlock`처럼 **고객 번호 1을 고정**으로 부른다. 설계상 해제는 사람만 하므로 이 노드를 지우고 관리자 콘솔 해제만 남긴다.
- `.github/workflows/`가 비어 있다 → PR마다 `pytest`·`npm run build`·`check_secrets.py`를 돌리는 CI 추가.
- `backend/requirements.txt`에 Jupyter 관련 패키지가 섞여 있다(`pip freeze` 결과) → 실행용·개발용 분리.
- `account_hash`로 계정을 찾을 때 전체 고객을 훑는다 → `email_hash` 컬럼·인덱스.
- 이벤트 중계기(event-relay)로 n8n 장애 시에도 이벤트를 잃지 않게.

## 4. 느낀 점 (초안 — 본인 말로 고칠 것)

- 기능을 만드는 것과 남이 그대로 다시 세울 수 있게 만드는 것은 다른 일이었다. 팀 저장소만으로는 내 PC에서도 관제까지 다시 띄울 수 없었다.
- 보안 프로젝트에서 가장 먼저 새는 곳은 코드가 아니라 설정 파일이었다. 워크플로 한 번 내보낸 것이 토큰 노출로 이어졌다.
- 웹 담당이라도 내가 남기는 로그가 탐지 규칙의 입력이라는 점을 처음부터 맞췄어야 했다.
