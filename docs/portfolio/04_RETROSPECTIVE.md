# 04 · 개선점과 느낀 점

①~⑤는 팀 프로젝트 기간(10-19 ~ 11-04), ⑥~⑨는 포트폴리오로 혼자 다시 설치하면서(11-10) 겪은 것, ⑩·⑪은 수업 정리 노트(비밀창고 방어전·Wazuh 통합 실습)와 대조해 찾은 것이다.

## 1. 문제 → 원인 → 해결 → 결과

### ① 공개 저장소에 Discord 웹훅과 API 토큰이 남아 있었다
- **문제**: 개인 저장소로 옮기려고 점검하니 n8n 워크플로 JSON 5개에 Discord 웹훅 1개, 커밋 기록에 자동화 API 토큰 3개가 있었다.
- **원인**: n8n 에서 내보낸 워크플로에 HTTP 헤더 값(`X-API-Key`)과 웹훅 주소가 그대로 들어간다. 커밋 전 점검 단계가 없었다.
- **해결**: `scripts/sanitize_repo.py` — 기록 전체에서 값을 찾아 `git filter-repo` 로 치환. 워크플로는 `{{ $env.AUTOMATION_API_TOKEN }}` 처럼 환경변수를 읽도록 바꿈(`localize_monitoring.py`). pfSense 백업도 `sanitize_pfsense.py` 로 비밀번호 해시·개인키·OpenVPN 키·SSH 호스트 키 등 21개를 지움. 제출 전 `check_secrets.py --history`.
- **결과**: 커밋 246개 재작성, 값 4개 제거, 재검사 0건. 팀에 웹훅 재발급·토큰 교체를 요청.

### ② 계정 브루트포스 탐지 규칙이 실제 앱 로그와 맞지 않았다
- **문제**: Graylog `ED-08 동일 계정 브루트포스` 는 `rule:login-bruteforce AND username:*` 을 찾는다. 내가 만든 API 는 `event_type:auth.login.failed` 와 `account_hash` 로 남기고 `username` 은 남기지 않는다. 그래서 이 규칙은 모의 로그로만 검증됐고, 실제 앱 공격에는 반응하지 않았다.
- **원인**: 시험용 모의 로그 형식(D 담당)과 앱 표준 이벤트 형식(A, 본인)을 서로 확인하지 않았다. 이메일을 로그에 남기지 않기로 한 내 설계가 규칙 쪽에 전달되지 않았다.
- **해결**: 앱 로그 형식에 맞는 `ED-A1 | 계정 브루트포스(앱 로그)`(같은 `account_hash` 실패 ≥ 5 / 15분)와 n8n 알림을 만드는 스크립트 `graylog_add_account_bruteforce.py` 를 추가. n8n `판정(잠금)` 노드가 `username` 이 없어도 `account_hash` 로 잠금 대상을 만들게 수정.
- **결과**: 실제 HTTP 공격 → Graylog 탐지 → n8n 자동 잠금 → 관리자 해제까지 **7/7, 탐지·잠금 39.8초**(11-10). 이메일 원문은 Graylog 에 0건.

### ③ 멤버십 등급 구매 기능이 팀원 작업과 겹쳐 되돌렸다 (11-02 ~ 11-03)
- **문제**: 등급 직접 구매(카카오페이·모의 카드)를 붙였는데(`250b42c`), 같은 날 `main` 에 문경구 님의 멤버십 결제 작업(`725990c`)이 들어와 충돌.
- **원인**: 같은 기능을 두 브랜치에서 동시에 만들었다. 역할표상 웹은 A 였지만 기능 단위 담당을 정하지 않았다.
- **해결**: 결제 테이블 없이 `tid` 쿠키로 처리하도록 줄인 뒤(`74372f8`) 최종적으로 내 구현을 되돌리고(`5d62b7b`) `main` 의 구현을 살렸다.
- **결과**: 발표 전 충돌 없이 병합(PR #62). 이후 기능 시작 전에 이슈로 담당자를 먼저 적기로 함.

### ④ 자동 로그아웃 시간을 하루에 두 번 바꿨다
- **문제**: 1시간으로 늘렸다가(`602812c`) 같은 날 30분으로 줄임(`2132bde`).
- **원인**: 시연 편의와 보안 기준 사이에서 근거 없이 정했다.
- **해결**: 유휴 30분·최대 8시간을 `config.py` 상수로 두고 화면에 남은 시간을 표시. 테스트로 고정.
- **결과**: 값 하나만 바꾸면 되고 테스트가 확인한다.

### ⑤ 새 PC 에서 혼자 설치할 수 없었다
- **문제**: Graylog·n8n·Wazuh 실행 정의가 저장소에 없음, `.env.example` 에 앱이 읽는 값 8개 누락, 로컬 실행에서 관리자 화면 접근 불가, 시드 실행 불가.
- **원인**: 각자 PC 에서 설정하고 결과만 공유했다.
- **해결**: `monitoring.compose.yaml`, `compose.portfolio.yaml`(관리자 입구 8444, 시드 연결), `.env.example` 보완, 설치 가이드와 '팀 PC 에만 있던 설정' 점검표.
- **결과**: 본인 노트북에서 1·2단계를 처음부터 다시 세워 시나리오 2종을 재현(11-10). Wazuh(3단계)는 명령만 준비.

### ⑥ HTTP 재현이 6/8 에서 멈췄다
- **문제**: 로컬 HTTPS 로 브루트포스 시나리오를 돌리면 5-1(잠금 확인 403)·5-3(해제 후 로그인 200)이 모두 429 로 실패.
- **원인**: 로그인 처리 순서가 '시도 제한 검사 → 비밀번호 → 잠금 검사' 라서, 15분 제한 창이 남아 있는 동안에는 잠금 여부와 상관없이 429 가 먼저 나간다. 앱 내부 재현은 시각을 16분 앞당기는 방식이라 통과했고, 실제 HTTP 에서만 드러났다.
- **해결**: 제한 값 3개(`LOGIN_WINDOW_MINUTES`, `LOGIN_MAX_PER_ACCOUNT`, `LOGIN_MAX_PER_IP`)를 환경변수로 바꿀 수 있게 하고(기본값 유지), 시나리오 스크립트에 `--wait-minutes` 를 넣어 창이 지난 뒤 복구 단계를 확인하게 했다. 순서 자체는 '잠금 계정도 시도 횟수 제한을 받는다'는 의도라 바꾸지 않았다.
- **결과**: 시연용 1분 창으로 **8/8, 79초**. 테스트 150개 그대로 통과.

### ⑦ 팀 n8n 워크플로의 인시던트 등록 노드 10개가 꺼져 있었다
- **문제**: Graylog 알림은 n8n 까지 오는데 관리자 화면에 인시던트가 생기지 않았다. 앱을 부르는 노드 10개가 비활성 상태였고, 켜면 `invalid syntax` 오류가 났다.
- **원인**: 본문 식 `{{ JSON.stringify({… group_key||null}}) }}` 안의 `}}` 가 n8n 식을 중간에서 닫았다. 또 워크플로는 n8n 2.x 노드 버전을 쓰는데 1.x 로 띄우면 활성화가 안 됐다. Graylog 는 URL 허용 목록에 없는 주소로 알림을 보내지 않았다.
- **해결**: 팀 원본은 그대로 두고 수정본(`monitoring/n8n/workflows/portfolio/`)에서 `}}` → `} }` 로 띄어 쓰고 노드를 켬, n8n 2.40.0 고정, 허용 목록 정규식 추가.
- **결과**: EX-05 모의 공격 → 인시던트 자동 등록 **54.2초**.

### ⑧ 브라우저로는 로컬 로그인이 안 됐다
- **문제**: 스크립트로는 로그인 200 인데, 브라우저에서 같은 계정으로 로그인하면 "허용되지 않은 출처의 요청입니다"(403).
- **원인**: 내가 만든 로그인 API 는 CSRF 방어로 `Origin` 과 요청 Host 가 같은 출처인지 본다. 로컬 nginx 가 `proxy_set_header Host $host` 로 포트를 빼고 넘겨서 `https://localhost:8443` ≠ `https://localhost` 가 됐다. 스크립트는 `Origin` 을 보내지 않아 그동안 드러나지 않았고, 학원망은 443 이라 문제가 없었다.
- **해결**: 팀 `nginx.conf` 는 그대로 두고, 사본 `nginx.portfolio.conf` 와 본인 파일 `nginx-admin.conf` 를 `$http_host` 로 바꿔 `compose.portfolio.yaml` 이 붙이게 함.
- **결과**: 브라우저 로그인 정상, 캡처 7장 확보. 스크립트만 믿지 말고 실제 화면으로 한 번은 확인해야 한다는 걸 배웠다.

### ⑨ n8n 잠금 노드가 엉뚱한 값을 보내 400 이 났다
- **문제**: 탐지는 되는데 계정이 잠기지 않았다. n8n 실행 기록에서 `HTTP 계정 block 요청` 이 400 "입력값을 확인하세요".
- **원인**: 이 노드는 `판정(잠금)` 바로 뒤가 아니라 `대시보드 POST1`(인시던트 등록) 뒤에 연결돼 있어, `$json` 이 인시던트 등록 응답이었다. 그래서 `account_hash` 가 비어 있었다. 또 `X-Workflow` 이름이 관리자 '자동화 현황' 카드(`8-login-bruteforce`)와 달라 기록이 '없음'으로 보였다.
- **해결**: 수정본에서 요청 본문이 `$('판정(잠금)').item.json` 을 직접 읽게 바꾸고 `X-Workflow: 8-login-bruteforce` 로 맞춤.
- **결과**: n8n 실행 #14 `"locked": true, "result": "CREATED"`, 자동화 현황 '동작 중 · 계정 잠금 1'.

### ⑩ 응답에 보안 헤더가 하나도 없었다
- **문제**: 수업 실습(비밀창고 방어전 5단계)에서 심판이 공통으로 지적한 '첫 화면 보안 헤더'가 이 프로젝트에도 없었다. API·화면 응답 모두 `X-Content-Type-Options`, `X-Frame-Options` 등이 0개.
- **원인**: 인증·세션·CSRF 같은 앱 안의 방어에만 집중했고, 응답 헤더는 Nginx 가 할 일이라고 생각해 누구도 맡지 않았다.
- **해결**: Flask 의 모든 API 응답에 보안 헤더 5개와 `Cache-Control: no-store`(`backend/app/core/security_headers.py`), Nginx 화면 응답에 같은 헤더(본인 파일 `nginx.portfolio.conf`·`nginx-admin.conf`). 팀의 학원망 템플릿 `host-nginx.conf.example` 은 고치지 않고 아래 '팀에 제안할 개선점'에 남김. 테스트 4개 추가.
- **결과**: 백엔드 테스트 154개 통과. 배운 원칙 그대로 '앱 계층과 앞단(Nginx) 계층을 따로 막는다'.

### ⑪ Wazuh 경보가 Graylog 규칙에 닿는 길이 저장소에 없었다
- **문제**: 팀 규칙 ED-07·ED-WZ-02 는 `wazuh_rule_id` 필드를 찾는데, 그 필드를 만드는 Graylog 파이프라인과 Wazuh `syslog_output` 설정이 저장소에 없다. 새 PC 에서는 이 두 규칙이 절대 걸리지 않는다.
- **원인**: Wazuh 통합 실습 때도 '파이프라인이 스트림에 연결되지 않아 Last matched: Never' 였던 같은 지점이다. 화면에서만 설정하고 파일로 남기지 않았다.
- **해결**: 파싱 규칙 `monitoring/graylog/pipelines/wazuh_alert_parse.rule` 과 설치 가이드 3-1 절(입력·`syslog_output`·스트림 연결)을 추가.
- **결과**: 순서는 정리했지만 로컬 Wazuh 를 띄우지 못해 **미검증**. 다음 할 일 첫 번째.

## 4. 시간이 더 있다면

- n8n 워크플로 `신규 API - 계정 잠금 해제(관리자)` 가 `/api/admin/customers/1/unlock` 처럼 **고객 번호 1 을 고정**으로 부른다. 설계상 해제는 사람만 하므로 이 노드를 지우고 관리자 콘솔 해제만 남긴다.
- Discord 알림 문구가 `ED-A1` 을 몰라 '⚠️ 보안 이벤트' 로만 나온다 → `메시지` 노드에 앱 이벤트 이름표 추가.
- `.github/workflows/` 가 비어 있다 → PR 마다 `pytest`·`npm run build`·`check_secrets.py` 를 돌리는 CI.
- `backend/requirements.txt` 에 Jupyter 관련 패키지가 섞여 있다(`pip freeze` 결과) → 실행용·개발용 분리.
- `account_hash` 로 계정을 찾을 때 전체 고객을 훑는다 → `email_hash` 컬럼·인덱스.
- Graylog `ED-A1` 이 같은 실패를 15분 동안 매분 다시 이벤트로 만든다(알림은 유예로 1번) → 이벤트 저장을 줄이려면 검사 창을 앱 제한 창과 분리.
- Wazuh 를 로컬에서 실제로 띄워 logtest 결과를 남기고, 매니저 `ossec.conf` 를 팀에서 받아 저장소에 넣는다.

## 5. 느낀 점

팀 프로젝트를 하면서 이때까지 배운 부분을 다시 한 번 직접 해 볼 수 있어 좋았고, 혼자서는 부족했던 부분이나 이해가 안 되던 부분도 팀원들과 함께 확인할 수 있었습니다.

특히 수업에서 따로따로 배운 웹 로그인·로그 수집(Graylog)·자동 대응(n8n)·방화벽(pfSense)이 실제로는 하나로 이어져 있다는 것을 이번에 처음 체감했습니다. 제가 만든 로그인 기능이 남기는 로그 한 줄이 관제 담당 팀원의 탐지 규칙 입력이 되고, 그 결과가 다시 제 API 로 돌아와 계정을 잠그는 구조였기 때문에, 내 담당만 잘 만드는 것보다 서로의 형식을 맞추는 것이 더 중요했습니다.

발표 뒤 포트폴리오를 위해 제 노트북에 처음부터 다시 세워 보면서, 팀 기간에는 보이지 않던 문제를 여럿 찾았습니다. 기능을 만드는 것과 다른 사람이 그대로 다시 세울 수 있게 만드는 것은 다른 일이라는 것, 그리고 테스트가 통과해도 실제 화면에서 한 번은 확인해야 한다는 것을 배웠습니다.

다음 발표에서는 받은 피드백대로 목소리를 키우고 원고보다 청중을 보며 말하겠습니다.
