## 7. 배포 DB 연결·권한 점검 및 수정

- 확인한 PC2 Docker API는 root 권한이 남아 있으나 읽기 전용 Replica 192.168.3.18에 잘못 연결돼 있었습니다.
- 배포가 GRANT를 삭제한 증거는 없고, 확인한 원인은 DB 연결 대상 오류였습니다.
- Primary 192.168.3.19의 read_only/super_read_only 0/0을 확인했습니다.
- 로컬 루트 .env·backend/.env와 해당 Docker API의 DB_HOST만 Primary로 수정했습니다. DB 권한이나 Replica의 쓰기 제한은 변경하지 않았습니다.
- 수정 후 Docker API의 Primary 연결과 readiness HTTP 200을 확인했습니다.
- .env가 이미지에 포함되지 않도록 Docker 제외 규칙을 보완했습니다.
- 배포 환경은 외부 환경변수만 사용하고 필수 DB 설정 누락 시 명확히 실패하도록 수정했습니다.
- 읽기 전용 DB 연결은 readiness에서 DB_READ_ONLY/503으로 처리하도록 했습니다.
- 행 변경 없이 Primary·스키마·앱 DML 권한을 확인하는 check-db-access 명령을 추가하고 로컬 점검 통과를 확인했습니다.
- 현재 컨테이너 파일 수정은 재생성 시 사라질 수 있으므로 이미지 재빌드와 실제 배포 환경변수 설정이 필요합니다.
- Kubernetes 실제 Pod는 SSH 인증 문제로 직접 확인하지 못했습니다.
- 웹 일반 사용자 권한과 백엔드 DB 계정 권한을 구분했습니다. 로그인·결제 등 처리를 위해 백엔드는 필요한 쓰기 권한을 가져야 합니다.
